# Подоменное ограничение сертификата МинЦифры

Спасибо автору [статьи](https://habr.com/ru/articles/1066372/) за идею и публикацию корневого сертификата. Именно корневой в публичном доступе найти непросто. Все официальные инструкции провайдят выпускающий, чтобы вы точно его воткнули в систему глобально, выпустили корневой и поленились выпиливать из системы, устанавливая ограничения поверх.  

Альтернативно можно скачать по моей [ссылке](https://shadowof.space/vendor/russian_trusted_root_ca.cer).  

Нужен сайт с сертификатом от Russian Trusted Root CA, но не хочется добавлять этот CA в системное хранилище доверенных? Скрипт создаёт настройки для **Google Chrome с ограничениями по DNS-именам** на macOS, Debian и Windows.

Без сторонних Python-зависимостей, без автоматической установки сертификатов в «Связку ключей» и без отключения проверки HTTPS.

> Название дерзкое, но магии нет: это не защита от слежки и не VPN. Для разрешённых доменов вы всё равно доверяете выбранному центру сертификации.

## Как это работает

`index.py` читает домены из `domains.json` в корне проекта и сертификат `russian_trusted_root_ca.cer` в PEM или DER, затем создаёт файл для выбранной платформы:

| Платформа | Файл | Область установки |
| --- | --- | --- |
| macOS | `chrome-restricted-russian-ca.mobileconfig` | Текущий пользователь |
| Debian | `chrome-restricted-russian-ca.json` | Все пользователи Google Chrome |
| Windows | `chrome-restricted-russian-ca.reg` | Текущий пользователь (`HKEY_CURRENT_USER`) |

Файл содержит политику Chrome [`CACertificatesWithConstraints`](https://chromeenterprise.google/policies/ca-certificates-with-constraints/) с сертификатом в Base64 и списком `permitted_dns_names`. Сам скрипт ничего не устанавливает: настройки нужно применить вручную.

## Требования

- macOS с возможностью установки профилей, Debian с Google Chrome или Windows с Google Chrome.
- Google Chrome **132 или новее**.
- Python **3.8 или новее**, со стандартным модулем `ssl`. На Debian при необходимости: `sudo apt install python3`.
- Сертификат Russian Trusted Root CA в **PEM или DER**, сохранённый как `russian_trusted_root_ca.cer`. Расширение `.cer` само по себе не определяет формат.
- Отдельный OpenSSL и пакеты из pip для запуска не нужны.

## Быстрый старт

### 1. Подготовьте сертификат

Скачайте сертификат (ссылки в начале readme) и положите рядом со скриптом:

```text
ministry_of_truth_chrome_restrict/
├── index.py
├── domains.json
└── russian_trusted_root_ca.cer
```

Не берите корневой сертификат из случайного чата или чужого готового профиля. Перед использованием проверьте сведения о нём и сравните SHA-256-отпечаток с независимо полученным доверенным значением:

```bash
openssl x509 -in russian_trusted_root_ca.cer \
  -noout -subject -issuer -dates -fingerprint -sha256
```

Это дополнительная проверка, если OpenSSL установлен. Для DER добавьте `-inform DER`. В Windows также можно просмотреть файл через:

```powershell
certutil -dump .\russian_trusted_root_ca.cer
```

### 2. Укажите нужные домены

Откройте `domains.json` рядом с `index.py` и заполните JSON-массив строк. Например:

```json
[
    "example.org",
    "example.net"
]
```

Замените примеры на реально нужные DNS-имена. Не указывайте `https://`, порт или путь страницы.

- `example.org` разрешает сам домен **и его поддомены**.
- `.example.org` разрешает только поддомены, но не сам `example.org`.
- Это ограничения имён сертификата, а не фильтр URL: все DNS-имена в SAN сертификата должны укладываться в разрешённые области. Иногда одного имени из адресной строки недостаточно.
- Добавляйте только необходимые области, а не целые зоны вроде `ru`.

> В репозитории `domains.json` содержит пустой список `[]`: заполните его перед запуском. Пустой список, элементы нестрокового типа, URL, wildcard и IP-адреса отклоняются. Международные DNS-имена преобразуются в IDNA. Проверка синтаксиса не гарантирует, что вы выбрали безопасную область доверия. JSON не допускает комментариев и запятой после последнего элемента.

### 3. Создайте настройки

Запускайте команду **из каталога со скриптом и сертификатом**. `domains.json` всегда читается рядом с `index.py`, независимо от каталога запуска. Пути сертификата и выходного файла по-прежнему вычисляются относительно текущего рабочего каталога.

```bash
python3 index.py
```

В Windows используйте `py -3 index.py`. Домены на всех платформах задаются только в `domains.json`; параметр `--domain` больше не используется.

Платформа определяется автоматически: macOS → профиль, Linux → JSON для Debian/Google Chrome, Windows → REG. Можно создать настройки для другой системы:

```bash
python3 index.py --platform debian
python3 index.py --platform windows
python3 index.py --platform macos
```

`--cert /путь/к/сертификату.cer` задаёт сертификат, `--output /путь/к/файлу` — выходной файл. Без этих параметров сертификат читается и результат создаётся в текущем каталоге. Существующий выходной файл перезаписывается; у профиля macOS каждый раз новые UUID.

### 4. Установите и проверьте

#### macOS

```bash
open chrome-restricted-russian-ca.mobileconfig
```

Завершите установку в настройках macOS: найдите раздел **«Профили» / «Управление устройством»** (название и расположение зависят от версии системы). Профиль называется **«Chrome: Russian CA — выбранные домены»**. Перед подтверждением проверьте его содержимое.

#### Debian

Просмотрите JSON перед установкой. Для официального Google Chrome:

```bash
sudo install -d -m 755 /etc/opt/chrome/policies/managed
sudo install -m 644 chrome-restricted-russian-ca.json /etc/opt/chrome/policies/managed/chrome-restricted-russian-ca.json
```

Это обязательная политика для всех пользователей Chrome на машине; установка требует root. Если файл назначения уже существует, сначала сохраните его копию. Не добавляйте CA через `update-ca-certificates`: для этой настройки системное доверие не требуется. Chromium использует другой каталог политик и здесь отдельно не проверялся.

#### Windows

Просмотрите `.reg` перед импортом, особенно домены. Если значение `CACertificatesWithConstraints` уже есть, сохраните его: импорт заменит весь список сертификатов в этой политике, а не дополнит его.

Из PowerShell **под целевым пользователем** (повышение прав не требуется):

```powershell
reg import .\chrome-restricted-russian-ca.reg
```

Политика записывается как `REG_SZ` с JSON в `HKEY_CURRENT_USER\Software\Policies\Google\Chrome`. Не импортируйте файл от имени другого администратора: это изменит настройки его пользователя. Сертификат не добавляется в системное хранилище Windows. Политики компьютера или организации могут иметь приоритет.

#### Проверка на любой платформе

В Chrome:

1. Откройте `chrome://policy`.
2. Нажмите **Reload policies / «Обновить политики»**.
3. Найдите `CACertificatesWithConstraints`: убедитесь, что нет ошибок и в `permitted_dns_names` перечислены именно ваши домены.
4. При необходимости полностью перезапустите Chrome и проверьте нужный сайт.

Chrome может показать надпись «Управляется вашей организацией» из-за установленной политики. Это само по себе не означает подключение к чужому удалённому управлению.

## Ограничения и безопасность

- Настройки предназначены для Google Chrome, не для Safari, Firefox, Edge или всей системы.
- DNS-ограничения не равны запрету всех остальных типов имён: скрипт не задаёт `permitted_cidrs` для IP-адресов. В документации политики указано, что тип имён без ограничения разрешён.
- Если этот CA уже добавлен как доверенный через «Связку ключей», другую политику или другой профиль, новый профиль не отменяет такое доверие. Отдельно проверьте и уберите ненужные источники доверия.
- Скрипт проверяет возможность разбора сертификата и синтаксис доменов, но не подлинность CA, его отпечаток, сроки действия или уместность выбранных доменов. PEM-файл должен содержать ровно один сертификат.
- Скрипт не скачивает сертификаты, не делает сетевых запросов и не отключает проверку TLS. После установки Chrome использует сертификат согласно своим политикам.
- На рабочем или управляемом устройстве установка может быть запрещена, а настройки — переопределены администратором. Не обходите ограничения устройства.

## Как откатить

**macOS:** удалите профиль **«Chrome: Russian CA — выбранные домены»** в настройках системы.

**Debian:** удалите только установленный этим проектом файл (или восстановите его прежнюю копию):

```bash
sudo rm /etc/opt/chrome/policies/managed/chrome-restricted-russian-ca.json
```

**Windows:** если до установки значения не было, удалите только его, а не весь раздел Chrome:

```powershell
reg delete "HKCU\Software\Policies\Google\Chrome" /v CACertificatesWithConstraints /f
```

Если значение уже существовало, восстановите сохранённое значение вместо удаления. На любой платформе обновите политики или перезапустите Chrome и проверьте `chrome://policy`. Если других источников этой политики нет, она должна исчезнуть.

Удаление `.mobileconfig` с диска **не удаляет установленный профиль**. Сертификаты, ранее добавленные в «Связку ключей» вручную, этот профиль тоже не удаляет.

Для изменения списка доменов отредактируйте `domains.json`, создайте настройки заново и повторите установку для своей платформы. Если macOS не предлагает заменить старый профиль, сначала удалите его, затем установите новый и снова проверьте политику.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Ошибка чтения доменов | `domains.json` должен лежать рядом с `index.py` и содержать непустой JSON-массив строк в UTF-8. |
| Не найден файл сертификата | Он должен лежать в текущем каталоге под именем `russian_trusted_root_ca.cer`, либо задайте `--cert`. |
| Ошибка чтения сертификата | Нужен один сертификат X.509 в PEM или DER, не HTML-страница и не набор сертификатов. |
| Политика отсутствует или отмечена ошибкой | Версию Chrome, установку профиля, содержимое политики и ограничения управления устройством. |
| Сайт всё ещё выдаёт ошибку сертификата | Цепочку сертификатов, сроки действия и все DNS-имена в SAN. Причина может быть не в этом CA; не отключайте проверку HTTPS. |

## Что выкладывать в репозиторий

Скрипт, `domains.json`, тесты и README. Сертификаты (`*.cer`), профили (`*.mobileconfig`) и стандартные выходные JSON/REG исключены через `.gitignore`: каждый пользователь получает и проверяет сертификат самостоятельно, затем выбирает свои домены. Перед публикацией очистите `domains.json` до `[]`, если не хотите выкладывать свой список. Файлы с нестандартными именами из `--output` проверьте перед коммитом.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют генерацию файлов и валидацию входных данных. Применение политик в реальном Chrome на Debian и Windows нужно дополнительно проверить на этих системах через `chrome://policy`.
